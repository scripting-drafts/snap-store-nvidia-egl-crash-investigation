## Subsequent diagnostic hang (2026-10-28)

The user confirmed that `sudo apt install gdb` **did not** cause a hang, whereas executing the original `./scripts/analyze-core.sh 40117` **did make the system unresponsive**. The original script exported the retained core via `coredumpctl dump` and then invoked GDB with an all-thread, full-variable backtrace. The stage at which responsiveness was lost is **not known**; do not treat this as a confirmed GDB failure or an NVIDIA driver fault. The repository subsequently changed the script to metadata-only by default and added opt-in, limited stages.
